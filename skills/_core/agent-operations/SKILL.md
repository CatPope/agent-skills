# 서브에이전트 운영 기록

서브에이전트는 세션 안에서만 동작하는 실행 주체다. 역할을 새로 만들거나, 모델·권한·모니터링 방식 같은
반복 운영 규칙을 정하면 **해당 업무의 기존 스킬을 같은 작업에서 갱신**해 다음 세션에서도 적용되게 한다.

## 적용 시점

- 사용자 요청으로 서브에이전트를 생성·배정할 때
- 장기 실행의 정보 수집·로그 모니터·검증·코드 작업처럼 반복되는 에이전트 역할을 정할 때
- 에이전트의 모델, 수정 권한, 보고 형식, 재개 방식이 바뀔 때

## 기록 원칙

1. 먼저 어떤 업무 스킬이 그 에이전트 운영의 정본인지 정한다. 예: 논문 재현은 `paper-reproduction`,
   보고서 작성은 `research-report`.
2. 새 역할이 **반복 운영 규칙**이면, 에이전트를 생성한 같은 작업에서 정본 스킬에 다음을 짧게 기록한다.
   역할·사용 모델·읽기/쓰기 권한·보고해야 할 근거·세션 종료 후 복구 방법.
3. 일회성 탐색처럼 재사용 가치가 없는 배정은 스킬에 누적하지 않는다. 대신 결과와 근거 경로만 작업 로그에 남긴다.
4. 기존 스킬에 맞는 위치가 없을 때만 이 스킬을 정본으로 보완한다. 업무 스킬의 구체 규칙을 이 파일로 중복하지 않는다.

## 영속성과 모니터링

- `/compact`, 세션 종료, 에이전트 종료 뒤에는 서브에이전트가 상주하지 않는다. 완료 여부나 진행 상태를
  에이전트의 대화 기억에만 의존하지 않는다.
- 장기 실행은 프로젝트 폴더에 로그와 모델·단계별 산출물을 남긴다. 다음 세션에서 새 에이전트를 배정해
  로그·프로세스·결과 파일로 상태와 재개 지점을 복구한다.
- 로그 모니터 에이전트의 기본 권한은 읽기 전용이다. 코드·문서·데이터·실행 프로세스 변경은 사용자가
  명시적으로 허가한 별도 역할에서만 수행한다.

## 현재 확정된 적용 사례

  세부 보고 항목과 로그 경로 규칙은 `paper-reproduction` 스킬을 따른다.
