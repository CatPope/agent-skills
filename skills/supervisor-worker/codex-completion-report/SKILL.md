# Codex 작업 완료 보고서

Codex가 사용자에게 작업 완료를 알리기 전에, 검증 근거를 담은 한국어 보고서를 해당 프로젝트 폴더에 남긴다.
이 스킬은 Codex 전용이다. Claude Code 관리자의 `research-report`·구글독스 게시 업무를 대체하지 않는다.

## 구조화 JSON 보고와의 관계 (중요)

관리자가 `codex-delegate` 방식(`codex exec --output-schema`)으로 작업을 넘겼다면,
**완료 보고는 2층으로 나간다. 둘 중 하나를 생략하지 않는다.**

- **JSON 완료보고** — 스키마가 강제하는 기계 검증용
  (`summary`/`modified_files`/`commands_run`/`tests`/`unfinished`/`blocked`).
  관리자의 검토는 **이 필드들부터** 본다. 여기서 누락하면 검토가 통과되지 않는다.
- **이 보고서(마크다운)** — 사람이 읽는 상세 기록. 근거·수치·실행 방법·재현 절차.
  JSON이 담을 수 없는 맥락이 여기 들어간다.

작성한 보고서 경로(`reports/YYYY-MM-DD_<작업명>/report.md`)는 **JSON의 `modified_files`
에도 반드시 포함**한다. 두 산출물이 서로를 가리켜야 관리자가 대조할 수 있다.

미완·차단이 있으면 **JSON의 `unfinished`/`blocked` 에 먼저 올린다.** 마크다운에만 적고
JSON에 `unfinished: []` 로 보내면 관리자는 완료로 읽는다 — 이것이 가장 흔한 사고다.

## 적용 단위

- 사용자에게 하나의 완료 결과로 보고할 수 있는 구현, 버그 수정, 테스트, 벤치마크, 논문 재현 단위에 적용한다.
- 모델×단계별 임시 실행이나 재시도마다 별도 보고서를 만들 필요는 없다. 이들은 같은 작업 보고서의 실행 내역으로 묶는다.
- 작업이 차단되었으면 완료라고 쓰지 않는다. 대신 같은 형식으로 상태 보고서를 작성하고 차단 근거와 남은 조치를 명시한다.
- **DINOv2 Figure/Table의 패널 작업**은 `panel-completion-report` 스킬을 우선 적용한다. 해당 스킬은
  실행 방법과 간단한 코드 설명을 추가로 강제하며, 이 일반 완료 보고서 규칙도 충족한다.

## 저장 규칙

- 기본 경로: `<프로젝트루트>/reports/YYYY-MM-DD_<작업명>/report.md`
- 같은 작업을 갱신하면 기존 보고서를 덮어 숨기지 말고 보고서 안에 갱신 일시와 변경 내용을 누적한다.
- 로그는 복사하지 않고 프로젝트 내부의 영구 로그 경로(`results/logs/` 등)를 링크한다.
- 이미지·JSON·체크포인트 등 산출물도 프로젝트 내부 상대경로와 실제 파일명을 기록한다.
- 프로젝트에 이미 확정된 보고서 폴더/명명 규칙이 있으면 그 규칙을 우선한다.

## 필수 내용

1. **작업 개요** — 목적, 범위, 완료/부분완료/차단 상태.
2. **환경·입력** — 실행 환경, 주요 모델·데이터·seed·표본 규모.
3. **구현 내용** — 생성·수정 파일과 핵심 설계 결정. 원본 보존 여부.
4. **실행 방법** — 재현 가능한 명령, 주요 인자, 단계 순서.
5. **결과** — 정량 지표와 대표 산출물. 직접 실행과 인용 수치를 구분.
6. **검증** — 수행한 테스트, 컴파일/정적 검사, 로그 완료 표식, 시각 검수.
7. **제약·남은 일** — 실패·차단·통계적 한계와 사용자 결정이 필요한 항목.

## 완료 게이트

- 보고서에 적는 수치와 상태는 결과 JSON·로그·파일을 직접 확인한 근거여야 한다.
- 테스트를 실행하지 못했으면 그 이유를 적고 테스트 완료로 표현하지 않는다.
- 실행 로그가 임시 경로에만 있으면 완료 처리하지 말고 프로젝트 폴더에 영구 보존한다.
- 보고서 작성 후 프로젝트의 `작업내역.md`가 있으면 보고서 경로와 한 줄 결과를 append한다.
- 최종 응답에는 보고서와 대표 산출물의 절대 경로 링크를 포함한다.
- Google Docs 업로드·관리 문서 편집은 Claude Code 관리자 범위이며, 사용자의 별도 지시와 승인 없이 수행하지 않는다.

## 프로젝트별 적용

- 프로젝트 루트·경로 규칙은 **그 프로젝트의 문서**(`AGENTS.md`·계획서)를 따른다.
  이 스킬에 특정 프로젝트 경로를 적지 않는다 — 다른 프로젝트에서 그대로 쓰기 위해서다.
- 보고서: `reports/YYYY-MM-DD_<panel-or-task>/report.md`
- 로그: `results/logs/`
- 결과 보고서에는 반드시 `feature_protocol`, 데이터 축소 조건, seed, 직접 실행 여부, FLOPs 산정법,
  데모 표본의 통계적 한계를 포함한다.
